# Companion UI

Use a fixed preview-led shell: app tabs and actions above the preview, timeline below it, and the device inspector on the right. Keep the preview visible, primary controls reachable and text unclipped at different window sizes and scales. Provide a compact inspector rail when space is limited. Splitters resize regions; folding the inspector or timeline must leave a way to reopen them. Focus mode keeps an obvious exit.

Controls edit live values without Apply. Show pending or rejected edits and ownership clearly. Use concise labels, tooltips and contextual help. Keep launch, connection, input capture, pause, inspection and restart workflows accessible. Release held desktop controls when capture ends or the active app changes.

The rig view represents simulated devices, not the game world. Looking back selects retained history without pausing the app; a take restores simulator inputs, not game state. Distinguish preview history from an exact retained snapshot. Show unavailable data as unavailable, and acknowledge a pause only when the runtime confirms it.

Keep selection and live state in their existing owners rather than duplicating them in panels. Independent app tabs retain their own inspection and timeline state. Background apps continue their activity without continuously importing preview images. Closing a tab with an active recording, replay or headset connection requires a clear shutdown flow.

Player, head, hands, body, gaze and trackers are device pages. Use visible handles for placement and numeric fields for precision. Keyboard/mouse and gamepad input should support play without requiring an inspector.
